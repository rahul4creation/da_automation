1. Purpose and Scope

This SOP explains how to configure and run the DA Report Review UI on another Windows user system, how to validate selected Excel reports, and where to find the generated review files.

Current validation mode: The duplicate UI uses Excel files for design validation and data validation. PDF input files are not required for the current UI review run.
Current UI visibility: Source Files, Review Stages, Quality Checks, Reconciliation Evidence, Artifacts, and Agent Output are hidden in the operator UI. The visible operator flow is Agent Inputs, Checklist Workbook Editor, Correction Observations From Review Files, and Review File Repository.

3. Prerequisites on Another User System

  1. Install Windows-compatible Node.js 20 or higher.
  2. Install Python 3.10 or higher if checklist revision scripts or agent helper scripts require Python.
  3. Install Google Chrome or allow Playwright Chromium to run for PDF/SOP generation and browser automation.
  4. Copy the full D:\AIReview project folder or restore the same folders listed in Section 2.
  5. Confirm the user has read/write permission for D:\AIReview\project and the input folders.
node -v
npm -v
python --version

4. UI Configuration

Open D:\AIReview\da_automation\DA AUTOMATION UI\.env and confirm the host/port settings.

APP_HOST=127.0.0.3
APP_PORT=5190
APP_PREVIEW_PORT=4190

API_HOST=127.0.0.3
API_PORT=8802
Port note: If another system cannot use 127.0.0.3, change both APP_HOST and API_HOST to 127.0.0.1. If port 5190 or 8802 is already in use, choose a free port and update the matching value in .env.

11. Report Selection Rules

  • Select only related report families together. Analog reports should be validated with Analog reports.
  • SAIFI/SAIDI reports should be validated with SAIFI/SAIDI reports.
  • For SAIFI/SAIDI hierarchy validation, Feeder Wise is the base report. Child reports such as Circle, Division, Subdivision, Zone, and Feeder Category are checked by grouping Feeder Wise data to the matching hierarchy level.
  • Unrelated families such as Analog and SAIFI/SAIDI should not be cross-compared as direct report pairs.
  • If selected reports are mixed or not recognized as one family, the output is categorized under Miscellaneous.

12. Checklist Workbook Editor

Screenshot 5: Checklist Workbook Editor with browse, latest revision option, sheet selection, and save revision.
  1. Use Checklist Selection in the editor to browse or select the checklist workbook to edit.
  2. Enable Always select latest checklist revision when the newest revision should load automatically after page open, refresh, or save.
  3. Select the required sheet in Checklist Sheet.
  4. Click Refresh Sheet to reload workbook rows.
  5. Click Add Row to add a new checklist point.
  6. Edit the checklist point text in the grid.
  7. Click Save Edited Revision. A new workbook revision is created and old files are kept.

Revision sequence follows: Rev 0.0 to Rev 0.10, then Rev 1.0 to Rev 1.10, continuing in the same pattern.

13. Run Review

Before clicking Run Review: Confirm the project name, checklist selection, and Excel report selection. The Run Review button remains disabled until the required selections are present.
  1. Click Run Review.
  2. Wait for the agent to finish. Large Excel workbooks or many selected files can take longer.
  3. After completion, a popup appears: Review files generated successfully.
  4. Close the popup after confirming the generated files list.
  5. Review the matrix cards, correction observations, and repository files.

16. Output File Location

All generated review files are saved under the project repository root:

D:\AIReview\project\<Project Name>\<Report Category>\<DD-MM-YYYY HH-MM-SS>\
Report Category FolderWhen It Is UsedExample
Analog ReportsSelected Excel report headers indicate Analog reports only.D:\AIReview\project\UPCL REPORT\Analog Reports\20-07-2026 16-04-50\
Saifi Saidi ReportsSelected Excel report headers indicate SAIFI/SAIDI reports only.D:\AIReview\project\UPCL REPORT\Saifi Saidi Reports\20-07-2026 16-04-50\
MiscellaneousSelected files are mixed, unknown, or not one recognized family.D:\AIReview\project\UPCL REPORT\Miscellaneous\20-07-2026 16-04-50\
Windows folder-name rule: The UI displays date/time as dd-mm-yyyy hh:mm:ss, but the actual timestamp folder uses hyphens in the time, for example 20-07-2026 16-04-50, because Windows folder names cannot contain colons.

Existing generated files are kept. A new run creates a new timestamp folder; no previous review files are deleted by the UI workflow.

17. Generated Review Files

A successful run can generate the following artifacts inside the timestamp folder:

  • *-design-review.pdf - design review PDF.
  • *-excel-data-validation.pdf - Excel data validation PDF.
  • *.txt - text summary for quick review.
  • *.md - Markdown review summaries.
  • *.json - structured review result.
  • *-design-check-matrix.xlsx - design matrix workbook.
  • *-data-validation-check-matrix.xlsx - data validation matrix workbook.
  • *-ui-run-summary-*.json - UI run summary metadata.

The review files include the UI project name and the logged-in reviewer name.

#User CheckExpected Result
